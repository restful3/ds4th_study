상세 리포트 표 2 · 소스별 통합 책임 /
ds4th studyLLM BOUNDARY

이 장에서 LLM은 구축의 권위가 아니다

정형·반정형 소스 통합에서는 deterministic한 매핑과 제약이 먼저이고, LLM은 분석 결과를 해석하는 후단에 놓입니다.

KG PIPELINE

기계적으로 고정할 일

  • node key와 `MERGE`로 중복 억제
  • UMLS·DOID·gene ID 같은 매핑 유지
  • 소스와 관계 의미를 질의 가능하게 보존

LLM LAYER

사람이 읽을 설명으로 바꿀 일

  • GO 과정과 DWPC 결과의 의미 요약
  • 임상시험 설계 질문 후보 생성
  • 검토자가 따질 후속 질문 정리

경계 — LLM 응답은 검증된 사실 저장소가 아니라, 사람이 검토할 설명 후보입니다.

ds4th studyINTERPRETATION LIMIT

도메인 집합과 알고리즘 커뮤니티를 섞지 않는다

질병 관련 단백질 집합은 도메인 지식으로 정의되고, Louvain 커뮤니티는 그래프 구조로 계산됩니다.

CAN SAY

말할 수 있는 것

  • PPI 대부분은 하나의 큰 WCC에 속한다.
  • Louvain은 내부 밀집 커뮤니티를 관찰했다.
  • 질병 경로는 외부 연결이 강한 경우가 많다.
CANNOT SAY

말하면 안 되는 것

  • 큰 WCC가 하나의 기능 단위라는 단정
  • 커뮤니티가 질병 경로와 1:1 대응한다는 단정
  • 지표만으로 개별 질병 원인을 확정

실무 규칙 — 지표는 후보를 좁히고, 원인과 조치는 추가 근거와 도메인 검토가 결정합니다.

ds4th studyDECISION GUIDE

도입 판단은 문제의 모양으로 한다

멀티소스 KG가 맞는 문제는 식별자, 경로, 다단계 관계, 검토 책임을 함께 갖고 있습니다.

GOOD SIGNAL

도입 가치가 커지는 조건

  • 공통 코드나 매핑 경로가 있다.
  • 연결성, 경로, 커뮤니티가 핵심 질문이다.
  • 결과를 거절·보류·추적할 책임자가 있다.
  • 그래프 질의가 SQL 기준선보다 복잡도를 줄인다.

WARNING SIGNAL

다른 접근이 나은 조건

  • 단일 테이블 필터와 집계로 충분하다.
  • 문자열 이름만 있고 동의어·동명이인이 많다.
  • 품질 기준과 소유자가 없다.
  • LLM 설명을 바로 최종 판단으로 쓰려 한다.

최소 질문 — 같은 엔티티를 정렬할 수 없으면, 그래프 분석 이전에 통합 품질부터 무너집니다.
