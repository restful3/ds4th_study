EXECUTIVE SUMMARY

핵심은 더 큰 모델이 아니라 역할 분담이다

LLM은 자연어와 비정형 데이터를 다루는 인터페이스이고, 지식 그래프는 사실·관계·맥락·검증 경로를 관리하는 지식 계층이다. 두 기술의 결합 가치는 한쪽이 다른 쪽을 대체할 때가 아니라 각자 잘하는 책임을 맡을 때 커진다.

이 장의 한 문장

LLM이 지식을 읽고 말하게 하고, 지식 그래프가 그 말의 근거와 최신성을 붙잡게 한다.

LLM

언어 인터페이스

문서를 이해하고 개체·관계를 추출하며, 복잡한 질문과 결과를 자연어로 연결한다.

KNOWLEDGE GRAPH

지식 계층

개체, 의미 있는 관계, 속성과 출처를 명시해 사람이 검증할 수 있는 구조를 만든다.

HYBRID

운영 루프

추출 → 검증 → 통합 → 질의 → 근거 기반 응답을 반복하며 지식을 계속 갱신한다.

읽기 관점

이 장은 특정 그래프 제품이나 RAG 구현법을 고르는 장이 아니다. 왜 두 기술이 필요한지, 각각 어느 책임을 맡아야 하는지, 어떤 문제에서 결합 가치가 커지는지를 정리하는 개념 지도다.

SECTION 01 · KNOWLEDGE GRAPH

지식은 연결에 의미가 붙을 때 비로소 작동한다

지식 그래프는 현실 세계의 대상을 노드로, 대상 사이의 의미 있는 연결을 관계로, 판단에 필요한 맥락을 속성으로 표현한다.

노드·관계·속성

노드(node)는 사람, 조직, 질병, 약물처럼 구분할 수 있는 개체다. 관계(relationship)는 두 개체가 어떻게 연결되는지를 이름으로 드러낸다. 속성(property)은 날짜, 용량, 설명, 출처처럼 개체와 관계를 해석하는 데 필요한 세부 맥락을 제공한다.

1약물 A승인일 · 용량
치료한다 →
2질병 B분류 · 설명
유발한다 →
3증상 C중증도 · 빈도

중요한 점은 데이터가 연결됐다는 사실 자체가 아니다. 연결에 치료한다, 유발한다처럼 해석 가능한 이름이 있고, 대상의 유형과 속성이 함께 있을 때 기계는 경로를 탐색하고 규칙을 적용하며 결과의 근거를 설명할 수 있다.

왜 유용한데도 널리 쓰기 어려웠나

BUILD

구축 비용

여러 데이터 원천에서 개체와 관계를 찾고 공통 스키마에 맞춰 지속적으로 정제해야 한다.

ACCESS

질의 장벽

여러 홉을 탐색하려면 그래프 구조와 전용 질의 언어를 이해해야 한다.

DELIVERY

결과 해석

답이 여러 노드와 관계에 흩어져 있어 비전문가가 바로 이해할 설명으로 바꾸기 어렵다.

정형 데이터는 필드와 유형이 이미 나뉘어 있어 공통 그래프 스키마로 매핑하는 과정이 비교적 예측 가능하다. 비정형 텍스트는 다르다. 언어·문체·오타·전문 용어뿐 아니라 대명사가 무엇을 가리키는지까지 해석해야 하므로 전통적인 정보 추출 파이프라인은 도메인마다 많은 규칙과 학습 데이터를 요구했다.

접근성의 문제

좋은 지식 그래프를 만드는 것만으로는 충분하지 않다. 사용자가 자연어로 질문하고, 시스템이 적절한 경로를 찾아 근거와 함께 읽기 쉬운 답으로 돌려줘야 지식이 실제 애플리케이션이 된다.

SECTION 02 · LARGE LANGUAGE MODEL

LLM은 자연어라는 접근 장벽을 낮춘다

전이 학습은 과제마다 전용 모델을 만드는 방식을, 이미 언어 패턴을 익힌 큰 모델에 과제를 지시하는 방식으로 바꿨다.

전이 학습이 만든 전환

관점과제별 전용 모델사전학습 모델·LLM
출발점각 과제용 라벨 데이터와 모델대규모 말뭉치에서 배운 일반 언어 패턴
새 과제 대응데이터 수집과 재학습프롬프트, 예시 또는 제한적인 조정
KG 구축 영향도메인마다 개체·관계 추출기 개발하나의 모델을 여러 추출 과제에 재사용

트랜스포머 기반 사전학습 모델은 다양한 자연어 처리 과제를 하나의 큰 모델로 다룰 수 있음을 보여줬다. 모델 규모, 학습 말뭉치의 양과 품질, 다음 토큰 예측이라는 공통 학습 목표가 결합되면서 자연어로 과제를 기술하고 결과를 생성하는 범용 인터페이스가 가능해졌다.

강점과 한계를 같은 표에서 본다

LLM이 잘하는 일LLM만으로 불안한 일
비정형 문서에서 개체와 관계 후보 찾기도메인 사실의 정확성과 최신성 보장
복잡한 자연어 질문의 의도 해석답이 어떤 사실과 경로에서 나왔는지 추적
검색 결과를 사람이 읽기 쉬운 글로 요약동일한 개체와 관계의 일관된 식별·관리
다양한 문체와 언어에 유연하게 대응그럴듯한 오류와 오래된 지식 억제
데이터 중심 관점

모델의 크기만 키우는 것으로 신뢰성이 해결되지는 않는다. 어떤 지식을 제공하고, 어떻게 검증하며, 어떤 근거를 답과 함께 내보낼지가 하이브리드 시스템의 핵심 설계 문제다.

SECTION 03 · MUTUAL REINFORCEMENT

둘의 결합은 단방향 검색보다 넓다

LLM은 지식 그래프를 만들고 이용하기 쉽게 하고, 지식 그래프는 LLM의 응답을 최신의 검증 가능한 사실에 연결한다.

LLM → KG

구축·질의·요약

문서에서 개체와 관계 후보를 추출하고, 자연어 질문을 그래프 질의로 바꾸며, 여러 노드의 결과를 설명으로 합친다.

KG → LLM

정확성·최신성·설명 가능성

검증된 도메인 사실을 제공하고, 지속 갱신되는 지식을 연결하며, 답을 만든 관계 경로와 출처를 남긴다.

운영 가능한 하이브리드 루프

1수집문서·정형 데이터
→
2추출개체·관계 후보
→
3검증·통합스키마·출처·정합성
4자연어 질의의도·경로 변환
→
5그래프 탐색관련 사실·경로
→
6근거 기반 응답요약·출처·설명
운영 원칙

LLM이 추출했다는 이유만으로 사실이 되지는 않는다. 추출 결과를 스키마와 검증 규칙에 통과시키고, 출처와 함께 지식 그래프에 통합하는 단계가 반드시 필요하다.

SECTION 04 · DATA APPLICATIONS

애플리케이션마다 지식을 복제하지 않는다

전통적인 데이터 애플리케이션은 목적별 데이터베이스와 로직을 따로 만들기 쉽다. 지식 그래프는 여러 애플리케이션이 공유하는 의미 있는 지식 원천을 지향한다.

그래프 패턴 매칭과 순회는 테이블 하나가 아니라 연결 구조 자체를 질문의 대상으로 만든다. 사람과 기계가 함께 해석할 수 있는 개체 유형, 관계와 규칙을 공통 지식 계층에 두면 검색·추천·분석·대화형 인터페이스가 같은 사실과 맥락을 재사용할 수 있다.

지식 그래프의 네 기둥

EVOLUTION

진화

새 데이터와 관계를 기존 구조를 전면 재설계하지 않고 계속 받아들인다.

SEMANTICS

의미

개체의 유형과 관계의 뜻을 명시해 일관성 검사와 추론의 근거를 만든다.

INTEGRATION

통합

형식과 출처가 다른 정형·비정형 데이터를 도메인의 의미를 중심으로 연결한다.

LEARNING

학습

질의·규칙·네트워크 분석과 머신러닝을 통해 명시되지 않은 통찰을 끌어낸다.

단일 진실의 원천

모든 데이터를 무조건 한곳에 복사한다는 뜻이 아니다. 동일한 개체와 관계를 해석하는 공통 의미, 식별자, 출처와 검증 규칙을 공유한다는 뜻에 가깝다.

SECTION 05 · USE CASES

결합 가치는 관계와 대화가 모두 중요할 때 커진다

이 장은 신약 발견과 고객 지원을 통해 서로 다른 도메인에서도 같은 역할 분담이 반복된다는 점을 보여준다.

신약 발견과 개발

문제지식 그래프LLM결합 결과
유전자·질병·약물·화합물과 문헌을 맥락을 잃지 않고 통합해야 한다.유형화된 관계와 규칙으로 생물학적 개체의 상호작용을 모델링한다.논문과 임상 보고서에서 개체·관계 후보를 찾고 텍스트를 연결한다.검증된 지식 기반을 확장하고 검색·가설 생성·텍스트 마이닝을 지원한다.

고객 지원 대화형 AI

문제지식 그래프LLM결합 결과
범용 모델의 답은 자연스럽지만 구체적인 고객·제품·정책 맥락이 부족할 수 있다.고객, 제품, 계약, 정책과 해결 절차를 의미 있는 관계로 연결한다.질문 의도를 이해하고 관련 지식을 대화 흐름에 맞는 문장으로 구성한다.복잡한 질문에도 사실에 기반하면서 자연스러운 응답을 제공한다.
공통 패턴

도메인 지식이 여러 원천에 흩어져 있고, 관계를 따라가야 답을 찾을 수 있으며, 사용자는 자연어로 묻고 싶어 한다면 하이브리드 접근의 후보가 된다.

SECTION 06 · RDF VS LPG

두 패러다임은 경쟁 제품이 아니라 표현 선택지다

이 책은 RDF와 LPG 어느 하나를 정답으로 고정하지 않는다. 필요한 의미 규칙과 질의 패턴을 기준으로 선택하고 함께 사용할 수도 있다.

관점RDFLPG
기본 표현주어–술어–목적어 트리플의 집합레이블이 있는 노드·엣지와 각 요소의 속성
대표 질의SPARQLopenCypher, Gremlin
강점표준, 연합, 상호운용성, 의미적 일관성관계 속성, 경로 탐색, 그래프 순회
잘 맞는 상황여러 데이터셋을 웹 규모에서 연결하고 온톨로지 추론이 필요할 때애플리케이션 중심 그래프 분석과 관계 단위의 풍부한 속성이 필요할 때

RDF의 관계는 지식 베이스 전체에서 재사용되는 전역 술어에 가깝고, LPG의 엣지는 고유한 정체성과 속성을 가질 수 있다. 따라서 관계 하나에 출처·시간·신뢰도 같은 속성을 직접 붙이는 모델과, 표준화된 술어로 여러 그래프를 연결하는 모델은 서로 다른 장점을 갖는다.

SECTION 07 · JUST ENOUGH SEMANTICS

그래프 구조만으로는 지식이 완성되지 않는다

분류체계와 온톨로지는 개체와 관계의 의미를 기계가 사용할 수 있는 규칙으로 바꾼다.

TAXONOMY

분류체계

탈것 ⊃ 자동차 ⊃ 세단처럼 범주를 넓음–좁음의 계층으로 조직한다.

ONTOLOGY

온톨로지

동일성, 역관계, 서로소, 개수 제약처럼 계층을 넘어선 개념 규칙을 명시한다.

전통적인 온톨로지는 모든 개념을 완전하게 정의하려다 경직되고 유지하기 어려워질 수 있다. 현대적인 지식 그래프는 당면한 문제를 해결하는 데 필요한 규칙부터 넣고, 도메인과 요구가 커지면서 부분 온톨로지를 확장하는 딱 필요한 만큼의 의미를 지향한다.

실무 기준

완벽한 세계 모델을 먼저 만들지 않는다. 현재 답해야 하는 질문, 검증해야 하는 일관성, 설명해야 하는 관계를 지원하는 최소 의미 규칙부터 시작한다.

DECISION GUIDE

기술 이름보다 문제의 모양을 묻는다

아래 질문에 여러 개가 해당할수록 지식 그래프와 LLM을 함께 검토할 이유가 커진다.

지식 그래프 신호

  • 서로 다른 데이터 사일로를 하나의 도메인 관점으로 연결해야 하는가?
  • 정형·비정형 원천 사이에서 동일한 개체와 관계를 추적해야 하는가?
  • 새 데이터와 구조를 계속 수용하는 유연한 표현이 필요한가?
  • 답의 출처와 관계 경로, 파이프라인 일관성을 검증해야 하는가?
  • 검색·추천·네트워크 분석이 관계의 구조를 활용해야 하는가?

LLM 신호

  • 문서에서 도메인 개체와 관계 후보를 찾아야 하는가?
  • 사용자의 복잡한 자연어 질문을 구조화된 질의로 바꿔야 하는가?
  • 대화형 인터페이스와 후속 질문이 필요한가?
  • 여러 경로의 결과를 사람이 읽기 쉬운 설명으로 요약해야 하는가?
함께 쓸 신호

관계를 따라 검증 가능한 사실을 찾아야 하면서, 사용자는 자연어로 묻고 답을 설명으로 받고 싶어 할 때 결합 가치가 가장 분명하다.

APPENDIX · GLOSSARY

핵심 용어

지식 그래프(KG)
유형이 있는 개체, 속성과 의미 있는 관계로 도메인 지식을 표현한 진화하는 그래프 구조
LLM
대규모 텍스트로 사전학습되어 자연어 이해와 생성을 수행하는 언어 모델
노드·관계·속성
현실의 대상, 대상 사이의 의미 있는 연결, 해석에 필요한 세부 맥락
홉(hop)
그래프에서 한 노드에서 인접한 다른 노드로 이동하는 한 단계
전이 학습
일반 과제에서 학습한 표현과 패턴을 다른 과제에 재사용하는 방식
환각
언어 모델이 사실이 아닌 내용을 그럴듯하게 생성하는 현상
GraphRAG
그래프의 구조와 관련 지식을 검색해 LLM 응답의 맥락으로 제공하는 접근
Text-to-Cypher
자연어 질문을 그래프 질의 언어 Cypher로 변환하는 작업
RDF·SPARQL
트리플 기반 지식 표현 표준과 그 데이터를 질의하는 언어
LPG
레이블이 있는 노드·엣지와 속성을 중심으로 표현하는 그래프 모델
분류체계
범주를 상위–하위 관계로 조직한 계층 구조
온톨로지
동일성·차이·제약 등 도메인 개념과 관계의 의미 규칙
