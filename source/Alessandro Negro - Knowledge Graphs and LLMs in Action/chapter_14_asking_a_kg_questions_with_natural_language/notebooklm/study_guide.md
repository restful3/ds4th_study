# 자연어 기반 지식 그래프(KG) 질의 시스템 구축 스터디 가이드

이 가이드는 지식 그래프(Knowledge Graph, KG)를 활용하여 자연어 질문에 답하는 고급 시스템을 구축하는 방법론을 다룹니다. 전통적인 검색 증강 생성(RAG)의 한계를 분석하고, 숙련된 분석가의 사고방식을 모방하는 '전문가 에뮬레이션(Expert Emulation)' 프레임워크를 중심으로 핵심 개념을 정리합니다.

---

## 1. 핵심 개념 요약

### RAG의 한계와 전문가 에뮬레이션
*   **RAG의 취약성:** RAG 시스템은 검색 단계에서 단 하나의 핵심 문서만 놓쳐도 완전히 상반된 결론을 내릴 수 있습니다(예: 목격자 진술 하나가 누락되어 범인의 주 손잡이를 잘못 판단하는 경우).
*   **전문가 에뮬레이션:** 숙련된 도메인 전문가는 단순히 문서를 읽는 것이 아니라, 지식 그래프의 **스키마(Schema)**를 이해하고 이를 바탕으로 정밀한 탐색(Traversal)을 수행합니다. 시스템이 이러한 전문가의 추론 패턴을 모방하도록 설계하는 것이 핵심입니다.

### 시스템 아키텍처의 4대 기둥
1.  **의도 탐지(Intent Detection):** 사용자의 질문이 데이터 질의인지, 시스템 도움말 요청인지, 아니면 피드백인지 분류하고 적절한 시각화 방식(그래프, 표, 차트, 지도)을 결정합니다.
2.  **스키마 추출 및 표현:** 기술적인 데이터베이스 스키마를 LLM이 이해하기 쉬운 **개념적 스키마**로 변환하고, 속성 값의 의미나 관계의 모호성을 해결하기 위한 주석(Annotation)을 추가합니다.
3.  **전문가적 추론 및 질의 생성:** LLM이 정답을 내기 전에 먼저 추론 과정을 거치도록 유도(Chain-of-Thought)하여 정확한 Cypher 질의를 생성하게 합니다.
4.  **응답 요약 및 통찰 추출:** 검색된 원시 데이터에서 불필요한 정보를 걸러내고, 사용자의 질문에 직접적으로 부합하는 핵심 요약을 제공합니다.

### 스키마 최적화 전략
*   **기술적 스키마 vs. 개념적 스키마:** 관리용 노드나 불필요한 기술적 메타데이터를 제거하고 도메인 핵심 엔티티와 관계만 남긴 '개념적 스키마'를 사용해야 LLM의 인지 부하를 줄이고 질의 오류를 방지할 수 있습니다.
*   **설명적 주석:** "BLK"가 "Black"을 의미한다는 식의 약어 설명이나 관계의 구체적인 의미를 주석으로 추가하여 자연어와 데이터 구조 간의 간극을 메웁니다.

## 2. 단답형 연습 문제

**질문 1:** RAG 시스템에서 '검색 단계의 불완전성'이 초래하는 가장 큰 위험은 무엇입니까?
**정답:** 불완전한 문맥으로 인해 모델이 확신을 가지고 틀린 결론(할루시네이션 및 논리적 오류)을 내릴 수 있는 취약성입니다.

**질문 2:** 전문가가 자연어 질문을 그래프 데이터베이스 질의로 변환할 때 사용하는 '도시 설계도'와 같은 역할을 하는 것은 무엇입니까?
**정답:** 그래프 스키마(Graph Schema).

**질문 3:** 의도 탐지 단계에서 사용자가 "지난해 지역별 범죄 발생 분포"를 물었을 때 적절한 시각화 유형은 무엇입니까?
**정답:** 차트(Chart) 또는 지도(Map).

**질문 4:** LLM에게 "먼저 추론하고 나중에 답변하라"고 명령하는 것이 중요한 이유는 무엇입니까?
**정답:** LLM의 '의미적 일관성(Semantic Consistency)' 경향 때문입니다. 답변을 먼저 내뱉으면 나중에 나오는 추론은 논리적 분석이 아닌 초기 답변을 정당화하는 수단으로 전락할 위험이 있습니다.

**질문 5:** 스키마 추출 과정에서 불필요한 노드나 속성을 제외하기 위해 사용하는 설정 항목의 명칭은 무엇입니까?
**정답:** 스킵 리스트(Skip List).

## 3. 심층 탐구를 위한 에세이 주제

### 주제 1: RAG 프레임워크와 전문가 에뮬레이션 방식의 근본적 차이점 분석
*   **핵심 질문:** 정보의 원천이 '문서 조각(Passages)'인 경우와 '구조화된 지식 그래프(KG)'인 경우, LLM이 정보를 처리하는 방식과 정확도 측면에서 어떤 차이가 발생하는지 서술하십시오.

### 주제 2: 지식 그래프 시스템에서 '의도 탐지'의 다층적 역할
*   **핵심 질문:** 단순한 질문 분류를 넘어, 의도 탐지가 하위 파이프라인 선택(데이터 vs. 시스템 관련) 및 최종 시각화 방식 결정에 어떻게 기여하는지 그 가치를 논하십시오.

### 주제 3: LLM을 위한 스키마 엔지니어링의 중요성
*   **핵심 질문:** 데이터베이스의 기술적 명세(Technical Schema)를 그대로 LLM에게 전달할 때 발생하는 문제점을 나열하고, 이를 '개념적 스키마'로 큐레이션하는 과정이 질의 생성 성공률에 미치는 영향에 대해 설명하십시오.

## 4. 주요 용어 사전

| 용어 | 정의 |
| :--- | :--- |
| **Cypher** | Neo4j와 같은 그래프 데이터베이스에서 데이터를 질의하기 위해 사용하는 선언적 질의 언어. |
| **Chain-of-Thought (CoT)** | 모델이 복잡한 문제를 풀 때 단계별 추론 과정을 거치도록 유도하는 프롬프트 엔지니어링 기법. |
| **Semantic Consistency** | LLM이 이전에 생성한 토큰과 논리적으로 일치하는 방향으로 이후 토큰을 생성하려는 경향. |
| **Conceptual Schema** | 기술적 복잡성을 제거하고 도메인 전문가의 시각에서 핵심 엔티티와 관계만을 요약한 데이터 구조 모델. |
| **Scratchpad** | LLM이 최종 결과를 도출하기 전에 중간 계산이나 추론 단계를 기록하는 논리적 작업 공간. |
| **Intent Detection** | 사용자의 입력을 분석하여 질문의 목적(데이터 검색, 시스템 사용법, 피드백 등)을 분류하는 프로세스. |
| **Constrained Traversal** | 스키마에 정의된 경로를 따라 특정 조건(필터링)을 적용하여 데이터를 탐색하는 과정. |
| **Expert Emulation** | 특정 분야 전문가의 지식 탐색 경로와 사고방식을 시스템적으로 모방하여 구현하는 방법론. |
