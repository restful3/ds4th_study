# 온톨로지를 활용한 첫 번째 지식 그래프 구축 학습 가이드

이 가이드는 정형 데이터 소스, 특히 온톨로지를 활용하여 지식 그래프(Knowledge Graph, KG)를 구축하는 과정과 주요 개념을 체계적으로 학습하기 위해 제작되었습니다. 의료 도메인의 희귀 질병 진단 사례를 중심으로 핵심 기술과 구축 방법론을 다룹니다.

---

## 1. 핵심 개념 요약

### 지식 그래프 구축의 필요성과 도전 과제
지식 그래프 구축은 서로 다른 형식(XML, CSV, JSON), 저장 기술, 구문 및 데이터 의미를 가진 이질적인 데이터 소스를 통합하는 복잡한 과정입니다. 특히 의료 분야에서는 동일 개념에 대한 다양한 표현(예: 제2형 당뇨병 vs 인슐린 비의존성 당뇨병)이나 동일 약어의 중복 의미(예: PE - 신체 검사 vs 폐색전증) 등이 데이터 통합의 장애물이 됩니다.

### 의미론적 통합과 온톨로지
*   **온톨로지(Ontology):** 데이터의 표준 어휘집이자 참조 스키마 역할을 합니다. 정식 명칭, 속성, 카테고리, 엔티티 간의 관계를 정의합니다.
*   **매핑(Mapping):** 데이터 소스의 로컬 스키마를 온톨로지의 참조 스키마로 연결하는 가교 역할을 합니다.
*   **시맨틱 통합:** 온톨로지를 사용하여 이질적인 정보 간의 의미적 차이를 해결하고 일관된 뷰를 생성하는 전략입니다.

### CRISP-DM 모델 기반 구축 단계
지식 그래프 구축은 데이터 마이닝을 위한 표준 프로세스인 CRISP-DM 모델의 일부 단계를 따릅니다.
1.  **비즈니스 이해 (Business Understanding):** 해결하려는 문제와 도메인을 분석합니다. (예: 임상의의 질병 진단 지원)
2.  **데이터 이해 (Data Understanding):** 사용 가능한 데이터 소스를 파악합니다. (예: HPO 온톨로지 및 어노테이션 데이터)
3.  **데이터 준비 (Data Preparation):** 관련 데이터를 선택하고 전처리합니다.
4.  **KG 모델 생성/업데이트 (KG Model Creation/Update):** 데이터를 그래프 형태로 모델링하고 통합합니다.

## 2. 지식 그래프 기술 비교: RDF vs. LPG

지식 그래프를 구현하는 두 가지 주요 접근 방식의 특징은 다음과 같습니다.

| 특징 | RDF (Resource Description Framework) | LPG (Labeled Property Graph) |
| :--- | :--- | :--- |
| **정의 주체** | W3C (표준 프레임워크) | 데이터베이스 벤더 중심 |
| **기본 구조** | 주어-술어-목적어의 트리플(Triple) | 노드(Node)와 관계(Relationship/Edge) |
| **강점** | 데이터 교환, 온톨로지 정의, 시맨틱 정밀도 | 빠른 쿼리 탐색, 경로 분석, 효율적인 저장 |
| **속성 표현** | 관계 자체에 속성을 직접 붙이기 어려움 (RDF-star 등으로 보완 중) | 노드와 관계 모두에 키-값 쌍 속성 추가 가능 |
| **주요 용도** | 웹상의 데이터 교환, 복잡한 도메인 모델링 | 데이터 탐색 중심의 애플리케이션, 분석 |

**※ 선택 기준:** 임상의가 특정 어노테이션의 출처, 날짜 등 풍부한 메타데이터를 확인해야 하는 경우, 관계에 직접 속성을 부여할 수 있는 **LPG** 방식이 더 직관적이고 효율적입니다.

## 3. 단답형 연습 문제

**문제 1:** 데이터 소스의 로컬 스키마와 온톨로지의 참조 스키마를 연결하여 데이터 요소를 온톨로지 개념에 매핑하는 과정을 무엇이라고 합니까?
> **정답:** 매핑(Mapping) 또는 어노테이션(Annotation)

**문제 2:** RDF 모델에서 관계에 속성을 추가하기 위해 제안된 새로운 사양으로, RDF와 LPG 간의 간극을 좁히려는 기술의 명칭은 무엇입니까?
> **정답:** RDF-star (RDF*)

**문제 3:** HPO(Human Phenotype Ontology) 데이터에서 질병과 표현형 이상 사이의 연결 정보를 포함하며, 증거 수준이나 빈도 정보를 담고 있는 파일의 형식은 무엇입니까?
> **정답:** TSV (Tab-Separated Values) 또는 HPOA 형식

**문제 4:** Neo4j 환경에서 RDF 데이터를 가져오고 OWL, RDFS와 같은 온톨로지 어휘를 사용하여 기본 추론을 실행할 수 있게 해주는 플러그인의 이름은 무엇입니까?
> **정답:** Neosemantics (n10s)

**문제 5:** 지식 그래프에서 논리적 규칙을 사용하여 명시적으로 저장되지 않은 암시적 정보를 도출하는 과정을 무엇이라고 합니까?
> **정답:** 추론(Reasoning) 또는 연역적 추론(Deductive Reasoning)

## 4. 심화 탐구를 위한 에세이 주제

### 주제 1: 의료 도메인에서 온톨로지 기반 지식 그래프의 역할
임상의가 희귀 질병을 진단할 때 직면하는 어려움(데이터 파편화, 불확실성 등)을 설명하고, HPO(Human Phenotype Ontology)와 같은 표준화된 어휘 체계가 어떻게 이러한 문제를 해결하며 지식 그래프를 통해 어떤 가치를 창출하는지 논하시오.

### 주제 2: 데이터 모델링의 관점에서 본 RDF와 LPG의 기술적 절충안
관계 메타데이터(Provenance, Date 등)를 표현하는 방식에 있어 RDF(n-ary 관계, 네임드 그래프 사용)와 LPG(직접 속성 부여)의 차이점을 분석하고, 특정 비즈니스 목표(예: 대규모 데이터 통합 vs 고성능 관계 탐색)에 따라 어떤 기술이 더 적합한지 사례를 들어 논하시오.

### 주제 3: 지식 그래프를 활용한 계층적 추론의 가치
단순한 키워드 검색과 비교하여, 온톨로지의 상하위 개념 관계(Subclass relationships)를 활용한 추론이 분석 결과의 풍부함을 어떻게 증대시키는지 설명하시오. (예: '내분비계 이상' 검색 시 하위 개념인 '갑상선 기능 저하증' 관련 질병까지 포함하는 과정)

## 5. 용어 사전 (Glossary)

*   **표현형 (Phenotype):** 질병에 걸린 개체에 나타나는 관찰 가능한 물리적, 생화학적 특성의 총합.
*   **질병 (Disease):** 특정 원인 세트, 경과 시간, 표현형 특징 그룹, 특정 치료에 대한 반응을 특징으로 하는 엔티티.
*   **HPO (Human Phenotype Ontology):** 표현형 이상에 대한 표준화된 정보와 질병 간의 연결성을 제공하는 리포지토리.
*   **트리플 (Triple):** RDF의 기본 단위로, 주어(Subject), 술어(Predicate), 목적어(Object)로 구성됨.
*   **공백 노드 (Blank Node):** RDF에서 전역 식별자 없이 관련된 정보를 그룹화하기 위해 사용하는 이름 없는 리소스.
*   **Cypher:** LPG 모델(주로 Neo4j)에서 사용하는 선언적 그래프 쿼리 언어.
*   **SPARQL:** RDF 모델의 데이터를 질의하기 위해 설계된 표준 쿼리 언어.
*   **의미론적 통합 (Semantic Integration):** 온톨로지를 참조 모델로 사용하여 데이터 소스 간의 의미적 이질성을 해결하는 전략.
