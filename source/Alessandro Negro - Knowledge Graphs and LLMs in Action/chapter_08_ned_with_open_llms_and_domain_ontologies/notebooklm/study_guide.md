# LLM과 도메인 온톨로지를 활용한 개체명 중의성 해소(NED) 학습 가이드

이 학습 가이드는 거대 언어 모델(LLM)과 도메인 온톨로지를 결합하여 복잡한 텍스트 내에서 개체의 정확한 의미를 식별하는 개체명 중의성 해소(Named Entity Disambiguation, NED) 시스템의 설계와 구현을 다룹니다.

---

## 1. 핵심 개념 정리

### 1.1 전통적인 NED 시스템의 한계 (scispaCy 사례)
전통적인 자연어 처리(NLP) 도구인 **scispaCy**는 생물 의학 도메인에 특화된 라이브러리이나 다음과 같은 한계가 있습니다.
*   **도메인 종속성:** 특정 도메인(생물 의학)에 국한되어 설계되었습니다.
*   **업데이트의 어려움:** 새로운 개체나 용어를 반영하기 위해 지식 베이스를 확장하고 업데이트하는 데 어려움이 있습니다.
*   **지식 활용의 미비:** 지식 베이스 내의 방대한 정보와 개체 간의 기존 관계 및 경로를 충분히 활용하지 못합니다.
*   **문맥 의존성:** "syndrome"이나 "congenital" 같은 명시적인 문맥 단어가 없을 경우, "Zika"와 같은 용어를 정확하게 식별하지 못하는 경우가 발생합니다.

### 1.2 LLM과 온톨로지 기반의 새로운 접근 방식
이 가이드는 오픈 소스 LLM(**Llama 3.1 8B**)과 도메인 온톨로지(**SNOMED**)를 결합하여 전통적인 시스템의 한계를 극복하는 다단계 NED 프로세스를 제시합니다.

#### **엔드투엔드(End-to-End) NED 프로세스**
1.  **개체명 인식 (NER):** 비정형 텍스트에서 질병, 유기체, 절차 등 사전에 정의된 카테고리에 해당하는 개체를 식별하고 라벨링합니다.
2.  **후보 선택 (CS):** 식별된 멘션(mention)에 대해 온톨로지 내에서 일치 가능성이 높은 후보 목록을 생성합니다. 효율성을 위해 Neo4j의 전체 텍스트 검색 기능을 사용합니다.
3.  **후보 중의성 해소 (CD):** 문맥 정보를 활용하여 여러 후보 중 가장 정확한 개체를 최종 선택합니다.

### 1.3 후보 중의성 해소(CD)의 3단계 전략
그래프 기반 알고리즘과 LLM의 강점을 결합하여 다음과 같은 세부 단계를 거칩니다.
1.  **최단 경로 탐색:** Neo4j의 GDS(Graph Data Science) 라이브러리를 사용하여 온톨로지 내 후보 개체 간의 최소 길이 경로를 식별합니다. 이 과정에서 범용적인 '허브 노드'는 제외하여 의미 있는 연결에 집중합니다.
2.  **경로-텍스트 변환 (Path-to-Text):** 그래프 경로를 자연어 문장으로 번역합니다. 이는 LLM이 텍스트 정보를 처리하는 데 최적화되어 있기 때문입니다.
3.  **텍스트 경로 요약:** 번역된 여러 문장을 하나의 요약된 문맥으로 압축하여 LLM의 인지 부하(토큰 수)를 줄이고 의사결정을 돕습니다.

## 2. 단답형 연습 문제

**질문 1:** 생물 의학 도메인 처리를 위해 spaCy 프레임워크를 기반으로 구축된 특화 NLP 도구의 이름은 무엇입니까?
> **정답:** scispaCy

**질문 2:** 본문에서 NED 시스템을 로컬 환경에서 실행하기 위해 사용한 오픈 소스 도구와 LLM 모델명은 무엇입니까?
> **정답:** Ollama, Llama 3.1 8B

**질문 3:** 450,000개 이상의 개념과 풍부한 관계 유형을 포함하고 있는 다국어 임상 용어 온톨로지의 명칭은 무엇입니까?
> **정답:** SNOMED (Systematized Nomenclature of Medicine)

**질문 4:** 후보 선택(CS) 단계에서 LLM을 사용하지 않고 Neo4j의 전체 텍스트 검색을 사용하는 주된 이유 두 가지는 무엇입니까?
> **정답:** 1) LLM 내부 지식 대신 도메인 온톨로지에서 직접 후보를 검색하기 위함, 2) 온톨로지의 크기가 너무 커서 전체를 프롬프트에 담을 수 없기 때문.

**질문 5:** 후보 중의성 해소 단계에서 그래프 경로를 자연어 문장으로 변환하는 이유는 무엇입니까?
> **정답:** LLM이 자연어 형태의 텍스트 정보를 처리하고 관계 정보를 해석하는 데 더 뛰어난 성능을 보이기 때문입니다.

## 3. 심층 탐구를 위한 에세이 질문

**주제 1: 전통적인 NLP 도구와 LLM 기반 NED 시스템의 비교**
*   scispaCy와 같은 사전 훈련된 모델 기반 도구와 Llama 3.1과 같은 범용 LLM을 도메인 온톨로지와 결합한 시스템의 차이점을 기술하고, 특히 지식 베이스의 업데이트와 관계 정보 활용 측면에서 어떤 이점이 있는지 논하십시오.

**주제 2: 그래프 데이터 과학과 LLM의 시너지**
*   NED 프로세스 중 '후보 중의성 해소(CD)' 단계에서 최단 경로 탐색, 경로-텍스트 변환, 요약 과정이 왜 필요한지 설명하십시오. 그래프 알고리즘이 제공하는 구조적 정보가 어떻게 LLM의 추론 능력을 강화하는지 구체적인 사례(예: Zika 바이러스와 소두증의 관계)를 들어 서술하십시오.

**주제 3: 로컬 LLM 배포의 전략적 가치**
*   Ollama를 통해 Llama 3.1 8B 모델을 로컬에 배포하여 NED 시스템을 구축할 때 얻을 수 있는 데이터 보안, 지연 시간(latency), 비용 측면의 이점에 대해 본문의 내용을 바탕으로 분석하십시오.

## 4. 주요 용어 사전 (Glossary)

| 용어 | 정의 |
| :--- | :--- |
| **NED (Named Entity Disambiguation)** | 텍스트 내의 모호한 개체 멘션을 지식 베이스나 온톨로지의 정확한 엔티티에 매핑하는 과정. |
| **NER (Named Entity Recognition)** | 비정형 텍스트에서 명명된 개체를 식별하고 질병, 생물체 등 정의된 범주로 분류하는 작업. |
| **SNOMED** | 45만 개 이상의 개념을 가진 방대한 의료 용어 체계로, 본 시스템에서 도메인 온톨로지로 활용됨. |
| **Ontology (온톨로지)** | 특정 도메인의 지식을 구조화하여 개념들과 그들 사이의 관계를 정의한 체계. |
| **Ollama** | 로컬 머신에서 LLM을 직접 실행할 수 있게 해주는 오픈 소스 도구. |
| **Llama 3.1 8B** | Meta에서 출시한 80억 개의 매개변수를 가진 오픈 소스 LLM으로, 다국어 처리와 효율적인 배포에 최적화됨. |
| **Neo4j GDS (Graph Data Science)** | 그래프 알고리즘(예: 최단 경로 탐색)을 실행할 수 있는 그래프 데이터베이스 엔진 라이브러리. |
| **Hub Nodes (허브 노드)** | 그래프 내에서 연결성(degree)이 매우 높은 노드로, 중의성 해소 시 노이즈를 줄이기 위해 제외되기도 함. |
| **Candidate Selection (후보 선택)** | 검색 기술을 사용하여 멘션과 일치할 가능성이 있는 온톨로지 내 후보군을 추려내는 단계. |
| **Path-to-Text Translation** | 지식 그래프의 경로 정보를 LLM이 이해하기 쉬운 자연어 문장으로 변환하는 기법. |
