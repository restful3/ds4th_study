# LangGraph 기반 지식 그래프 QA 에이전트 구축 스터디 가이드

이 가이드는 LangGraph를 사용하여 지식 그래프(Knowledge Graph, KG) 쿼리용 QA 에이전트를 구축하는 핵심 개념과 아키텍처, 구현 세부 사항을 다룹니다. 제공된 자료를 바탕으로 시스템의 구조와 작동 원리를 깊이 있게 이해할 수 있도록 구성되었습니다.

---

## 1. 핵심 개념 정리

### LangGraph 개요
*   **정의:** LLM을 기반으로 하는 상태 유지형(stateful), 다중 액터(multi-actor) 애플리케이션을 구축하기 위한 라이브러리입니다.
*   **핵심 구조:** 워크플로우를 유향 그래프(Directed Graph)로 구현하며, 각 노드는 특정 에이전트 기능을 나타내고 엣지는 실행 흐름을 결정합니다.
*   **상태 관리:** 에이전트 간에 데이터를 직접 주고받는 대신, '화이트보드'와 유사한 **공유 상태(Shared State)** 객체를 사용합니다. 각 에이전트는 이 상태를 읽고 자신의 작업 결과를 추가하여 업데이트합니다.

### 시스템 아키텍처 (전문가 에뮬레이션 접근 방식)
시스템은 크게 백엔드(LangGraph 파이프라인)와 프론트엔드(Streamlit)로 나뉩니다.

| 구성 요소 | 역할 |
| :--- | :--- |
| **LangGraph 파이프라인** | 의도 탐지, 스키마 추출, 쿼리 생성 및 실행 등 핵심 로직 오케스트레이션 |
| **구성 공급자 (Configuration Provider)** | 프롬프트 템플릿(Jinja2 사용) 및 시스템 설정 관리 |
| **스키마 공급자 (Schema Provider)** | 기술적 스키마를 LLM이 이해하기 쉬운 개념적 스키마로 변환 및 정제 |
| **질문 처리 인터페이스** | 파이프라인을 이벤트 스트림으로 노출하여 프론트엔드와 실시간 통신 |
| **Streamlit 프론트엔드** | 사용자 입력(질문, 선택), 시각화(그래프, 표, 지도) 및 요약 결과 표시 |

### 파이프라인 주요 단계
1.  **의도 탐지 (Intent Detection):** 질문에 적합한 시각화 유형(표, 그래프, 지도)을 결정합니다.
2.  **스키마 추출 (Schema Extraction):** 그래프 데이터베이스에서 필요한 노드와 관계 정보를 추출하고 정제합니다.
3.  **Text-to-Cypher:** 자연어 질문을 그래프 DB 쿼리 언어인 Cypher로 변환합니다.
4.  **쿼리 실행 (Query Execution):** 생성된 쿼리를 실행하고 결과를 데이터 프레임이나 리스트 형식으로 포맷팅합니다.
5.  **요약 생성 (Generate Summary):** 실행 결과를 바탕으로 자연어 요약과 분석을 제공합니다.

## 2. 단답형 연습 문제

**문 1. LangGraph에서 에이전트들이 정보를 공유하고 업데이트하기 위해 사용하는 중심 객체는 무엇인가?**
> **답:** 상태(State) 객체

**문 2. 텍스트 기반 리소스(프롬프트 템플릿 등)를 코드와 분리하여 관리하기 위해 사용되는 템플릿 언어는 무엇인가?**
> **답:** Jinja2

**문 3. 스키마 공급자가 기술적 스키마를 개념적 모델로 변환할 때, 불필요한 요소를 제외하기 위해 사용하는 목록의 명칭은?**
> **답:** 스킵 리스트(Skip list)

**문 4. 쿼리 실행 실패 시 시스템의 복원력을 높이기 위해 구현된 메커니즘으로, 최대 몇 번까지 시도되는가?**
> **답:** 재시도 메커니즘 (최대 3회 시도)

**문 5. 질문 처리 인터페이스가 파이프라인 실행 과정을 프론트엔드에 전달할 때 사용하는 데이터 전송 방식은?**
> **답:** 이벤트 스트림(Event stream) 또는 스트림 실행 모드

**문 6. 사용자가 그래프 상의 특정 노드를 선택하고 질문할 때, 이 시각적 맥락을 반영하여 쿼리를 생성하는 에이전트의 명칭은?**
> **답:** Text-to-Cypher 에이전트

## 3. 심층 탐구를 위한 에세이 주제

### 주제 1: 상태 기반 통신 아키텍처의 이점
LangGraph의 상태 기반 아키텍처가 기존의 에이전트 간 직접 데이터 전달 방식과 비교했을 때 갖는 장점은 무엇인지, '화이트보드' 비유를 들어 설명하시오. (특히 에이전트 간의 결합도 해제와 워크플로우 유연성 측면을 포함할 것)

### 주제 2: 기술적 스키마에서 개념적 스키마로의 변환 필요성
LLM에 원시 기술 스키마를 직접 제공하는 대신, 스키마 공급자를 통해 정제된 'LLM 친화적' 스키마를 제공해야 하는 이유는 무엇인가? 비즈니스 개념 설명 추가 및 노드 필터링의 역할을 중심으로 논하시오.

### 주제 3: 동적 라우팅과 조건부 엣지의 역할
파이프라인의 'Post-query execution' 단계에서 조건부 엣지(Conditional edges)가 어떻게 의도 탐지 결과나 실행 오류에 따라 흐름을 제어하는지 분석하고, 이것이 사용자 경험(UX) 개선에 기여하는 바를 기술하시오.

## 4. 주요 용어 사전 (Glossary)

| 용어 | 정의 및 설명 |
| :--- | :--- |
| **Cypher** | Neo4j 그래프 데이터베이스에서 데이터를 쿼리하고 조작하기 위해 사용하는 선언형 그래프 질의 언어. |
| **Jinja2** | 파이썬용 템플릿 엔진으로, 본 시스템에서는 프롬프트 템플릿의 동적 콘텐츠 생성을 위해 사용됨. |
| **Neo4j** | 노드와 관계를 사용하여 데이터를 저장하고 관리하는 그래프 데이터베이스 관리 시스템. |
| **Streamlit** | 데이터 분석 및 머신러닝 모델을 위한 대화형 웹 인터페이스를 신속하게 구축할 수 있게 해주는 파이썬 프레임워크. |
| **Stateful Application** | 실행 단계 간에 정보를 저장하고 기억하여, 이전 단계의 결과를 후속 단계에서 활용할 수 있는 애플리케이션. |
| **Event Stream** | 파이프라인의 진행 상황(의도 탐지 중, 쿼리 생성 중 등)을 실시간으로 업데이트하여 프론트엔드에 전달하는 데이터 흐름. |
| **Intent Detection** | 사용자의 질문 목적을 분류하여 적절한 시각화 방식(표, 그래프, 지도 등)을 선택하는 프로세스. |
| **Schema Annotation** | 지식 그래프의 요소에 대한 비즈니스 레벨의 설명이나 도메인 지식을 추가하여 LLM의 이해를 돕는 주석. |
