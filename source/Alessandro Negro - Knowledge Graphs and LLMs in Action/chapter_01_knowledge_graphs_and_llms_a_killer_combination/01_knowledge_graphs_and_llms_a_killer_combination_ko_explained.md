# 지식 그래프와 LLM: 환상의 조합 — 쉬운 해설판

> 이 글은 Alessandro Negro의 *Knowledge Graphs and LLMs in Action* 1장 "Knowledge
> graphs and LLMs: A killer combination"의 전체 내용을 빠짐없이 담되, 전문 용어와
> 개념을 풀어쓴 설명과 최소한의 비유로 재구성한 해설판입니다.

시작하기 전에 이 장 전체를 관통하는 두 주인공을 먼저 소개하겠습니다. 이 짝을 머릿속에
잡아두면 나머지 내용이 훨씬 술술 읽힙니다.

- **LLM(대규모 언어 모델)** 은 엄청난 양의 글을 읽어 박학다식하고 말솜씨가 뛰어난
  달변가입니다. 다만 가끔 아주 그럴듯하게 **없는 사실을 지어냅니다.**
- **지식 그래프(KG)** 는 검증된 사실만 구조적으로 정리해 둔 **사실 대장(색인)** 입니다.
  정확하지만, 아무나 꺼내 쓰기엔 다루기가 까다롭습니다.

이 장의 핵심 메시지는 간단합니다. **이 둘을 합치면 서로의 약점을 정확히 메워 준다** 는
것입니다. 이 비유는 앞으로 꼭 필요할 때만 다시 불러오겠습니다.

## Part 1. 하이브리드 지능형 시스템의 기초 — 이 책이 딛고 서는 땅

**지식 그래프(KG)** 와 **대규모 언어 모델(LLM)** 의 결합은 지능형 시스템 발전의
결정적 전환점입니다. 책의 이 첫 번째 파트는 서로를 보완하는 이 두 기술이 어떻게 힘을
합쳐 더 강력하고 효과적인 해법을 만들어내는지를 이해하기 위한 토대를 놓습니다.

이 두 기술을 통합하면, 각 접근법의 결정적 한계를 메우는 동시에 각자의 강점을 증폭할
수 있습니다. KG는 LLM에 흔히 부족한 **명시적이고, 검증 가능하며, 갱신 가능한 지식
표현** 을 제공합니다. 반대로 LLM은 복잡한 지식 구조를 훨씬 쉽게 접근할 수 있게 만드는
**자연어 이해·생성 능력** 을 제공합니다. 이 시너지 덕분에 다음과 같은 일을 해내는
지능형 시스템을 만들 수 있습니다.

- 정형 데이터와 비정형 데이터를 모두 효과적으로 다루기
- 여러 종류의 추론 전략을 결합하기
- 설명 가능하고 검증 가능한 결과를 내놓기
- 지식 베이스를 끊임없이 갱신하기
- 정확성과 신뢰성을 유지하면서 사용자와 자연스럽게 상호작용하기

**1장** 은 KG와 LLM이라는 강력한 조합을 소개하며, 둘이 서로를 보완하는 관계임을
확립하고, 구체적인 예시와 활용 사례를 통해 어떻게 서로의 능력을 끌어올리는지를
보여줍니다. 즉 이 하이브리드 접근법이 지닌 변혁적 잠재력을 이해할 무대를 마련합니다.

**2장** 은 지능형 시스템의 근본 개념을 파고들어, 서로 다른 유형의 **지식 표현
(knowledge representation)** 과 **추론 전략(reasoning strategy)** 을 깊이 있게
다룹니다. 지식 획득·표현, 그리고 다양한 형태의 추론에서 KG와 LLM이 각각 어떤 역할을
맡아 실제로 함께 작동하는지를 살핍니다.

이 두 장에서 소개하는 프레임워크와 개념은, 책의 나머지 부분에서 다룰 실전 구현과 고급
응용의 밑바탕이 됩니다.

## 1장. 지식 그래프와 LLM: 환상의 조합

### 이 장에서 다루는 내용

- 지식 그래프 소개하기
- 대규모 언어 모델 소개하기
- 지식 그래프와 대규모 언어 모델로 데이터 기반 애플리케이션 만들기

구글의 Gemini나 OpenAI의 GPT 같은 LLM이 이끄는 **생성형 인공지능(Generative AI,
GenAI)** 은 우리가 일하고 살아가는 방식을 바꿔 놓으며 온갖 산업을 차례로 혁신했습니다.
이런 성공에도 불구하고, 생성형 AI는 **특정 분야의 전문 지식, 높은 정확성, 설명
가능성** 이 필수인 영역에서는 힘을 못 씁니다. 게다가 다른 심각한 한계도 안고 있습니다.
바로 **환각(hallucination)**, 그리고 **맥락과 관계 정보의 부재** 입니다. 앞서 말한
달변가가 아는 척은 잘하지만 근거를 대라고 하면 흔들리는 상황과 같습니다. 바로 이
지점에서 **지식 그래프(KG)** 가 등장합니다. KG는 경험, 환경적 특성, 문화적 측면, 사회적
규범 같은 맥락 정보를 제공해, 임무 수행에 실패가 허용되지 않는 애플리케이션을 위한
이른바 **"AI의 제3의 물결"** [1]을 세울 수 있게 해 줍니다.

KG는 현실 세계의 **개체(entity)** — 사람, 장소, 질병, 단백질 등 — 를 표현하고, 그들
사이의 의미 있는 연결을 정의하며, 맥락을 부여하는 정교한 그래프 구조입니다. KG는
구조적이고 설명 가능한 지식 표현을 제공하지만, 만들고 질의하기가 까다롭습니다. 반대로
LLM은 자연어 처리 능력은 뛰어나지만 환각, 오래된 정보, 그리고 특정 도메인에 뿌리내리지
못하는 문제를 안고 있습니다. 이 둘을 합치면 **"환상의 조합(killer combination)"** 이
됩니다. LLM은 비정형 텍스트에서 개체와 관계를 뽑아내 KG를 더 효율적으로 구축하고, 더
자율적이고 강력한 그래프 질의·분석을 가능하게 합니다. 한편 KG는 신뢰할 수 있고 최신인
도메인 지식을 제공해 LLM의 답변을 사실에 붙들어 매고 환각을 막아 줍니다. 서로의 빈틈을
정확히 채워 주는 관계입니다.

KG와 LLM을 결합하는 것은, 서로 다른 데이터 원천을 조화시키고, 자연어 인터페이스를
제공하며, 맥락에 단단히 뿌리내린 지능적 응답을 내놓는 정교한 데이터 기반 애플리케이션을
만드는 강력한 접근법입니다. 이 책에서 여러분은 **비즈니스 중심의 접근법** 을 채택하고,
KG 스키마를 모델링하고, 개체 추출에 LLM을 활용하고, 정보의 무결성을 검증하고, 정형·비정형
데이터를 아울러 복잡한 도메인별 질문에 답하는 대화형 AI 시스템을 만드는 법을 배우게
됩니다.

### 1.1 지식 그래프 — 기계에 사람의 지식을 심는 법

KG는 사람의 지식을 **구조화된 형태로 기계에 담아**, 기계가 더 지능적으로 행동하게
만듭니다. 이를 위해 다음 세 가지 요소로 이루어진 정교한 그래프 구조를 만듭니다.

- **노드(Node)** 는 현실 세계의 개체를 나타냅니다 (사람, 장소, 조직, 질병, 단백질,
  유전자 등).
- **관계(Relationship)** 는 이 노드들 사이의 의미 있는 연결을 정의합니다 (어떤 사람이
  어떤 장소에서 태어났다, 어떤 질병이 어떤 증상을 일으킨다, 어떤 유전자가 어떤
  단백질을 암호화한다 등).
- **속성(Property)** 은 맥락을 제공합니다 (생년월일, 지리 좌표, 조직의 연혁, 여러
  언어로 된 질병 설명 등).

그림 1.1은 의료 분야의 KG를 보여 줍니다. 여기서 질병, 약물, 화합물, 해부학적 구조 같은
개체들이 의미 있는 관계로 연결되어 있습니다. 이렇게 지식을 **명시적으로** 표현해 두면,
기계는 구조화된 지식 위에서 추론(reasoning)과 추정(inference)을 수행할 수 있고, 이는
의사결정을 돕는 복잡한 지능형 시스템의 바탕이 됩니다.

이처럼 지능형 시스템 개발에 효과적이고 이점이 많은데도, KG는 여러 이유로 널리 채택되지
못했습니다. 대표적으로 다음과 같습니다.

- **비용이 큽니다.** 만들고 유지하는 데 시간, 노력, 돈이 많이 듭니다.
- **접근 방식이 까다롭습니다.** 여러 단계(hop)를 건너뛰며 탐색하려면 복잡한 접근
  패턴이 필요합니다.
- **결과가 흩어져 있습니다.** 원하는 정보가 여러 노드와 관계에 걸쳐 분산되어 있습니다.

KG를 구축하려면 정형·비정형을 아우르는 이질적인 데이터 원천에서 관련 있는 개체와 연결을
인식하고 뽑아내야 합니다. 이때 정형 데이터를 다루는 일은 비정형 데이터를 다루는 일보다
비교할 수 없이 수월합니다. 정형·반정형 데이터(관계형 데이터베이스, 혹은 CSV·XML·JSON
형식의 파일)에서는 각 항목이 이미 분리되어 있고, 식별되어 있으며, 흔히 유형까지 지정되어
있습니다. 물론 이런 데이터도 원래의 스키마에서 공통 그래프 스키마로 **매핑(mapping)**
해야 하지만, 그 과정은 통제 가능하고 예측 가능합니다.

![](images/96a7bce5f5b308d29d0f342b4b454200207666d10cbcafd83248e3131fd469ec.jpg)
그림 1.1 의료 도메인의 KG 예시. 노드(원)는 사람, 질병, 해부학적 부위 같은 개체를
나타냅니다. 엣지(관계)는 개체 사이의 의미 있는 연결을 나타냅니다. 노드와 엣지는 관련
세부 정보를 담은 속성을 가집니다.

비정형 데이터는 완전히 다른 이야기입니다. 텍스트에서 정보를 뽑아내는 일은 다음과 같은
이유로 늘 까다로운 과제였습니다.

- **여러 언어** — 언어마다 고유의 문법 규칙, 어휘, 관용구, 뉘앙스가 있습니다. 여러
  언어로 된 텍스트를 처리하려면 이런 차이를 이해하고 다룰 수 있는 시스템이 필요합니다.
  게다가 언어마다 고유한 문자 체계(라틴, 키릴, 한자 등)를 쓰기 때문에, 다양한 문자와
  인코딩을 지원해야 합니다.
- **오타** — 사람이 쓴 텍스트에는 오탈자, 맞춤법 오류를 비롯한 실수가 섞이기 마련이고,
  의도한 의미를 알아내려면 정교한 알고리즘이 필요합니다.
- **대명사** — 대명사가 무엇을 가리키는지 풀어내는 **상호참조 해소(coreference
  resolution)** 는 정확한 이해에 필수적입니다. 예를 들어 "John saw Bob and he waved
  (존이 밥을 봤고 그가 손을 흔들었다)"라는 문장에서 "he(그)"가 존인지 밥인지는
  분명하지 않습니다.
- **다양한 문체** — 저자들은 동의어를 쓰고, 문장 구조를 달리하며, 저마다 독특한
  표현을 씁니다. 그래서 시스템이 일관성을 유지하면서 서로 다른 문체를 정확히 해석하기가
  어렵습니다.
- **도메인 고유의 전문 용어와 개념** — 많은 전문 분야가 고유한 어휘, 기술 용어, 개념을
  쓰는데, 이를 정확히 이해하고 추출하려면 그 분야의 전문성이 필요합니다.

사람의 언어에서 정보를 정확히 뽑아내고 해석하려면 고도의 기법과 견고한 시스템이
필요합니다. 그런데 KG를 만드는 것은 시작일 뿐입니다. KG는 방대하고 서로 얽힌 정보(지식)를
담고 있는데, 질문에 대한 올바른 답을 얻고 지능형 시스템을 뒷받침하려면 이 지식에 **제대로
접근** 할 수 있어야 합니다. KG의 스키마를 유연하게 정의하면 이질적인 데이터 원천과 복잡한
도메인 연결을 다루기에 좋지만, 반대로 질의하는 법을 모르는 사람에게는 접근이 어려워집니다.
미리 정해 둔 질의와 분석을 쓰면 특정 지능형 시스템을 만들기엔 좋지만, 사용할 수 있는
사용자층과 시스템이 제공할 수 있는 지원의 폭이 제한됩니다. 그리고 그 결과는 비전문가나
서로 다른 사용자 인터페이스에서 해석하기 어려운 경우가 많습니다.

몇 가지 예를 봅시다. KG를 초기에 도입한 가장 유명한 사례는 **구글** 입니다. 구글은
KG를 이용해 "관련된" 연결 정보를 함께 제공함으로써 검색 품질을 끌어올렸습니다. 이
접근법은 단순한 **문자열(string)** 이 아니라 **사물(thing)** 그 자체를 검색한다는 점을
강조합니다. 다만 검색 애플리케이션에 국한된다는 한계가 있습니다.

많은 분석가가 복잡한 조사·수사성 질문에 답하기 위해 KG를 활용합니다. 그러나 그래프
질의 과정이 복잡하고 전용 인터페이스가 필요하기 때문에, 이런 활용은 소수의 사용자층에
머무릅니다.

이제 이런 장면을 상상해 봅시다. 사람들이 **자연어로** KG에 질문을 던지면, 지능형
시스템이 그래프를 효과적으로 질의해 올바른 답을 찾고, 그 결과를 알기 쉬운 요약으로
바꿔 돌려주는 모습을 말입니다. 이 책은 바로 이 시나리오를 처음부터 끝까지 함께
만들어 갑니다.

### 1.2 대규모 언어 모델 — 자연어라는 장벽을 허무는 열쇠

자연어를 다루는 데 특화된 LLM은, KG를 핵심 기술로 삼는 지능형 시스템의 발전을 가로막던
장벽을 걷어낼 수 있습니다. 이런 시스템은 사용자가 복잡한 도메인에서 원하는 일을
해내도록 도울 수 있습니다.

LLM의 토대는 **전이 학습(transfer learning)** 입니다. 전이 학습이란, 일반적인 과제
(예: 가려진 토큰 맞히기)에서 배운 패턴을 특정 과제(예: 관계 추출)에 다시 활용하는 능력을
말합니다 [2] (그림 1.2 참고). 이 돌파구는 패러다임을 뒤바꿔 놓았습니다. **과제마다
작은 전용 모델을 여럿 학습시키던 방식** 에서, **여러 과제에 두루 재사용할 수 있는
소수의 거대 모델을 학습시키는 방식** 으로 옮겨간 것입니다. 그 덕분에 지도 학습에
필요한 학습 데이터와 연산 자원이 크게 줄었습니다.

왜 이것이 그토록 중요한 전환일까요? 전이 학습 이전에는, 새 과제가 생길 때마다 그 과제
전용의 라벨링된 데이터를 대량으로 모아 모델을 처음부터 다시 학습시켜야 했습니다. 반면
전이 학습에서는 일반적인 언어 감각을 이미 익힌 거대 모델을 가져와 약간만 조정하면
되므로, 새 과제를 훨씬 적은 데이터로 해결할 수 있습니다. 우리가 KG 구축에 관심을 두는
이유도 여기 있습니다. 도메인마다 전용 NLP 모델을 훈련하는 대신, 이미 학습된 LLM 하나에
지시(프롬프트)만 바꿔 개체·관계 추출을 시킬 수 있게 되었기 때문입니다.

**트랜스포머(transformer) 아키텍처** [3]로 대규모 말뭉치에서 학습한 **사전학습 언어
모델(Pretrained Language Model, PLM)** 은, 단 하나의 큰 모델로 자연어 처리(NLP)
과제를 수행할 수 있음을 보여 주었습니다. 모델 규모를 키우자 모델의 능력이 커졌고,
규모 효과를 더 파고들면서 파라미터 규모는 계속 확장되었습니다. **대규모 언어 모델
(large language model)** 이라는 용어는, 파라미터가 보통 수백억 개에 이르는 상당한
규모의 PLM을 가리킵니다. 방대한 양의 텍스트로 학습한 GPT-2 [5] 같은 LLM의 등장은 AI
분야를 완전히 바꿔 놓았습니다. 그 현대적 후예인 GPT-4 [5], Gopher [6], PaLM [7]은

![](images/7d0090ad1c0bb754f736192e80945527f00f626bd121f26d24e488d41545f453.jpg)
그림 1.2 전이 학습에서는, 특정 과제로 학습한 모델(또는 그 일부)을 다른 과제의 학습과
예측에 가져다 씁니다.

**"데이터의 불합리한 효과성(unreasonable effectiveness of data)"** [8]이라는 표현에
새 생명을 불어넣었습니다. 이들의 성능이 **"불합리(unreasonable)"** 하다고 불리는 데는
서로 맞물린 세 가지 이유가 있습니다.

1. **모델 복잡도** (달리 말해 파라미터의 개수)
2. **학습 말뭉치의 크기** — 그리고 GPT의 경우엔 그 **품질**
3. 사람의 지능을 요하는 과제들을 **다음 토큰 예측(next token prediction)** 이라는
   하나의 문제로 환원해 내는 능력

논문 "신경 언어 모델을 위한 스케일링 법칙(Scaling Laws for Neural Language
Models)" [9]이 보여 주듯, 더 큰 신경망 모델(즉 학습 가능한 파라미터가 더 많은 모델)은
동일한 테스트셋 손실(성능) 수준에 도달하는 데 **더 적은 데이터 샘플** 을 필요로 합니다.
이는 얼핏 반직관적입니다. 보통 "더 큰 모델은 더 많은 데이터가 필요하다"고 생각하기
쉽지만, 실제로는 더 큰 모델일수록 데이터 한 조각에서 더 효율적으로 배운다는 뜻이기
때문입니다. 같은 논문은 학습 말뭉치의 크기가 지극히 중요함도 증명합니다. 당연하게도, 모델이 배울
데이터가 많을수록 성능이 좋아집니다. 하지만 **데이터의 품질** 도 그에 못지않게 중요합니다.
전통적인 머신러닝은 대개 **모델 중심(model-centric)** 패러다임을 따라, 최적의 모델
구조를 찾고 하이퍼파라미터를 미세 조정하는 데 집중했습니다. 그러나 잘못된 데이터는
잘못된 예측으로 이어집니다. **데이터 중심(data-centric)** 패러다임은, 고복잡도 ML
모델을 학습시키는 데 쓰는 데이터의 품질과 양을 모두 끌어올리기 위해 **데이터 엔지니어링**
을 우선시합니다. 이런 개선이 이루어지면, 우리는 과제를 자연어로 기술하기만 해도 LLM이
정확한 답을 생성하며, 별도의 모델 엔지니어링은 거의 필요 없어집니다 (그림 1.3 참고).

**토큰화(tokenization)** 는 텍스트를 **토큰(token)** 이라는 단위로 잘게 나누는
과정입니다. 이렇게 하면 텍스트 표현이 단순해져, 모델이 언어를 이해하고 처리하기가
쉬워집니다. 이 과정은 연산 효율을 높이고, 의미를 보존하며, LLM의 성능을 끌어올립니다.

### 1.3 KGs와 LLM은 함께일 때 더 강하다 — 서로를 떠받치는 관계

KG와 LLM은 더 나은 서비스를 제공하기 위해 서로를 떠받치며, 함께라면 강력한 지능형
시스템 구현을 한층 끌어올릴 수 있습니다. 특히 우리가 주목하는 것은, LLM이 KG 기반
솔루션을 돕는 다음 세 가지 방식입니다.

- **KG 구축하기** — 구체적으로는, 비정형 데이터에서 관련 개념과 연결을 뽑아내는
  작업입니다. 전통적으로 이 작업은 특정 도메인마다 맞춤형 NLP 모델을 학습시켜야 했습니다.
  LLM은 최소한의 설정(예: 프롬프트)만으로 여러 목적에 두루 쓸 수 있는 모델을 제공해 이
  과정을 크게 단순화했습니다 (그림 1.4 참고). KG 구축은 2부와 3부에서 다룹니다.
- **KG 질의하기** — 지식을 뽑아내는 일은, 출발 개념에서 목적지까지 여러 단계(hop)를
  거쳐야 할 수 있습니다. 이런 단계들을 밟으려면 흔히 스키마와 질의 언어를 이해해야
  합니다. LLM은 관련성 높고 정밀한 정보를 뽑아내 질의와 검색을 돕습니다. 이 내용은
  5부에서 다룹니다.
- **요약하기** — KG에서 뽑아낸 정보를 표, 그래프, 차트 같은 형식이 아니라 **글(텍스트)**
  형태로 돌려줄 수 있습니다.

![](images/7209372bfac79d98178b07a98a73abd41d52c6a2f1eacae69c5d92f0da46753c.jpg)
그림 1.4 LLM이 있을 때와 없을 때의 KG 구축, 그리고 질의·검색에 대한 LLM의 지원

거꾸로, KG도 LLM이 안고 있는 도메인 정확성·투명성·시의성 관련 한계를 극복하도록 도울
수 있습니다. KG를 통합함으로써 완화할 수 있는 LLM의 약점 몇 가지를 소개합니다 [10].

- **환각(Hallucinations)** — KG는 구조적이고 검증된 지식을 제공해 **사실의 토대** 역할을
  합니다. 그 덕분에 LLM이 그럴듯하지만 틀린 정보를 지어내려는 경향이 크게 줄어듭니다.
  반대로 LLM은 **텍스트-투-사이퍼(text-to-cypher) 변환** 같은 정교한 질의 메커니즘을
  제공해 이를 보완합니다. 이는 자연어 질문을 정밀한 그래프 질의로 바꿔, 구조화된 지식
  베이스에서 신뢰할 수 있는 정보를 직접 뽑아내게 해 줍니다. (앞서 소개한 달변가에게
  옆에서 사실 대장을 펼쳐 확인시켜 주는 셈입니다.)
- **오래된 정보(Stale information)** — KG는 진보된 검색 증강 구조를 통해 지식을 동적으로
  갱신할 수 있게 해 줍니다. LLM은 끊임없이 재학습시킬 수 없지만, KG는 계속 갱신할 수
  있고 **KG 기반 프롬프팅** 이나 **GraphRAG** 같은 기법으로 접근할 수 있습니다.
  GraphRAG는 지식을 의미 있는 군집과 커뮤니티 요약으로 조직해, 끊임없이 갱신되는 KG가
  보유한 가장 최신 정보를 LLM에 공급합니다.
- **설명 가능성(Explainability)** — KG는 사용자가 추적하고 검증할 수 있는 투명한 정보
  경로와 구조적 추론을 제공해, 설명 가능한 AI 과정을 통해 신뢰를 쌓습니다. 여기에 LLM의
  자연어 처리가 결합되면, 지식 추출 과정이 이해 가능하고 재현 가능하며, 그 결과를 사람이
  읽기 쉬운 형태로 요약할 수 있는 시스템이 완성됩니다.

그림 1.5는 이 두 기술이 어떻게 서로를 떠받치고 보완하는지를 정리해서 보여 줍니다.

### 1.4 데이터 기반 애플리케이션의 패러다임 전환 — 왜 판이 바뀌는가

전통적인 패러다임은 구조화되고 동질적인 데이터베이스를 바탕으로, 특정 목적에 맞춘
시스템을 만듭니다. 이 방식은 정해진 요구에는 잘 들어맞지만, 사용자 특성에 맞춰 적응하고
이질적인 데이터를 통합해야 하는 복잡한 도메인에는 비현실적입니다. KG는 연결을 포착해,
**그래프 패턴 매칭** 과 **순회(traversal)** 를 통해 관계를 발견할 수 있게 합니다.
**RDF(Resource Description Framework)** 와 **LPG(Labeled Property Graph)** 는 모두
사람이 해석할 수 있으면서 기계도 읽을 수 있는 형식을 제공합니다. KG는 사람과 기계가
모두 쓸 수 있는 풍부하고 의미 있는 데이터 표현을 강조하며, 이를 통해 지능적 행동이
**단일한 진실의 원천(single source of truth)** 에 담기는 패러다임 전환을 가능하게
합니다.

맥킨지앤드컴퍼니(McKinsey & Company)에 따르면 [12], **데이터 파편화(data
fragmentation)** 문제를 해결하면 단기적으로 연간 데이터 지출을 5~15%까지 줄일 수
있습니다. KG는 이렇게 사일로(silo)로 갈라진 데이터 문제를 극복해, 데이터 접근 장벽을
낮추고 거버넌스를 강화하면서 지식의 원천을 만들어 냅니다.

#### 1.4.1 지식 그래프의 네 기둥 — KG를 KG답게 만드는 것

이 패러다임 전환을 구체적인 구현으로 담아내기 위해, 저자들은 기술적 측면과 비즈니스적
측면에 두루 영향을 미치는 모든 특징을 아우르는 새로운 KG 정의를 제안합니다.

> **정의** 지식 그래프란, 유형이 지정된 개체들과 그 속성, 그리고 의미 있는 이름을 가진
> 관계들로 구성된, 끊임없이 진화하는 그래프 데이터 구조다. 특정 도메인을 위해 만들어지며,
> 정형 데이터와 비정형 데이터를 통합해 사람과 기계를 위한 지식을 빚어낸다.

이 정의는 KG의 **네 기둥** 을 위한 토대가 됩니다.

- **진화(Evolution)** — KG를 쓰면 정보를 끊임없이 수집·통합해 하나의 원천으로 통일할
  수 있습니다. 그래프 구조는 쉽게 확장되어, 분석의 필요와 우리의 목적에 따라 진화합니다.
  KG는 기존 구조를 완전히 뜯어고치지 않고도 새로운 상호작용이나 콘텐츠를 매끄럽게
  받아들일 수 있습니다.
- **의미(Semantics)** — KG는 데이터의 의미, 즉 **의미론(semantics)** 을 명시적으로
  드러내, 유형이 지정된 개체와 의미 있는 관계로 특징지어지는 지식 인프라 안에 정보를
  모델링합니다. 새 데이터는 기존 데이터와 결합되어 즉시 분석에 쓰일 수 있습니다. 이
  인프라에서 맥락적 지식이 떠오르고, 그것이 비즈니스 활동과 의사결정을 이끕니다. 이런
  지식은 분류를 기술하는 유형화된 개체들을 연결하며, 예컨대 동일성(identity), 이행적
  (transitive), 역(inverse) 관계 등을 뒷받침합니다. 이렇게 데이터를 풍부하게 표현하는
  능력은 **설명 가능성** 으로 가는 문을 엽니다 [13]. KG는 일관성 검사부터 인과 추론에
  이르는 다양한 추론 메커니즘의 척추 역할을 합니다.
- **통합(Integration)** — KG는 한 도메인과 관련된 모든 정형·비정형 데이터의 중심 기준점
  역할을 합니다. KG는 데이터의 의미에 초점을 맞춰 정보를 표현하기 때문에, 사용자는
  데이터의 유형·형식·출처와 관련된 난제를 넘어서서 여러 데이터 원천의 정보를 연결할 수
  있습니다.
- **학습(Learning)** — KG는 한 도메인의 핵심 정보와 큰 그림을 표현합니다. 사람은
  그래프 데이터를 분석·시각화·질의해 통찰을 뽑아낼 수 있습니다. 그 위에서 추론 규칙과
  머신러닝 알고리즘을 돌려, KG에 명시적으로 담겨 있지 않은 새로운 정보를 추정해 낼 수도
  있습니다. 분석가는 영향력 있는 노드를 찾는 **중심성·연결성 분석**, 노드 사이 최단
  경로를 탐지하는 **네트워크 분석**, 비슷한 노드들의 무리를 알아내는 **커뮤니티 분석**
  같은 방법을 활용할 수 있습니다.

### 1.5 KGs와 LLM으로 데이터 기반 애플리케이션 만들기

이 절에서는 중요한 분야에서 KG와 LLM을 활용할 수 있는 잠재적 응용 사례 몇 가지를
살펴봅니다.

> **참고** 이 책에서는 의료(healthcare) 분야를 자주 언급합니다. 의료 분야의 특성·문제·요구
> 사항이 다른 도메인에도 쉽게 옮겨 적용될 수 있기 때문입니다. 또한 의료 분야는 공개된
> 데이터가 풍부해서, 실제 활용 사례에 견줄 만한 데이터셋으로 현실적인 예시를 논할 수
> 있습니다.

#### 1.5.1 예시 사례: 신약 발견과 개발

신약 개발은 생물학에서 화학에 이르기까지 수많은 분야의 지식을 통합해야 하는 일입니다.
게다가 새 약을 시장에 내놓는 데는 비용이 많이 들고 실패 확률도 높습니다. 그래서 신약
개발 연구를 이끌어 줄 빠르고 실용적인 접근법이 꼭 필요합니다.

- **과제** — 의학·제약 데이터를 통합할 때는 각 데이터 지점을 올바른 맥락에 놓으면서도,
  데이터의 무결성·정확성·일관성을 보장해야 합니다.
- **KG 기반 해법** — 서로 다른 규모의 생물학적 개체들 사이의 상호작용을 모델링해,
  관계 유형을 이용해 유전자·질병·약물을 연결합니다. 여러 규칙을 가진 유형화된 관계는
  도메인의 의미를 더 잘 표현해, 이행적 연결과 추론을 가능하게 합니다.
- **LLM의 역할** — 과학 논문, 임상 보고서, 데이터베이스에서 온 비정형 데이터를 처리해,
  통합된 지식 베이스의 일관성을 보장합니다. LLM은 문헌을 분석하고 잠재적 관계를 추정해
  KG를 확장하며, 화학 구조와 실험 결과에 대한 정교한 텍스트 마이닝도 수행합니다.

LLM을 통합하면 데이터 통합이 강화되고, KG가 확장되며, 가설 생성이 쉬워지고, 정보 검색이
개선되며, 고급 텍스트 마이닝이 가능해집니다. 이런 능력은 궁극적으로 새로운 치료제 개발을
가속합니다.

#### 1.5.2 예시 사례: 고객 지원을 위한 대화형 AI

개인화된 어시스턴트 시스템은 사용자의 질의에 답할 뿐 아니라, 필요하면 되물을 줄도 알아야
합니다. 효과적인 도구가 되려면 일반적인 전문성과 사용자별 구체적 요청을 결합하면서,
방대한 정보를 효율적으로 관리해야 합니다.

- **과제** — 자연어 생성(NLG) 기법이 발전했음에도, 언어 모델의 답변은 반복적이고 알맹이가
  없을 수 있습니다 (Zhang 외 [14]). 대화형 시스템이 유용한 제안과 정보를 주려면,
  텍스트에서 관련 개체와 관계를 뽑아내는 동시에, 대화를 사실에 붙들어 매 줄 외부·내부의
  구조화된 지식의 뒷받침을 받아야 합니다.
- **KG 기반 해법** — Zhang 외 [14]는 **"대화는 흔히 지식을 중심으로 전개된다"** 고
  말합니다. 특히 자연스러운 대화는 그 지식을 이루는 개념들을 중심으로 흘러갑니다. KG는
  바로 그런 개념들을 연결하고 그 사이에 의미 있는 관계를 세웁니다. KG는 대화를 사실에
  붙들어 매고, 정보를 통합하며, 응답 생성을 뒷받침할 수 있습니다. NLP 기술이 개체와
  관계를 뽑아내고, 대화의 그래프 기반 배경 맥락이 대화 흐름을 이끕니다.
- **LLM의 역할** — LLM은 폭넓은 주제를 다루고 일관된 응답을 내놓을 수 있어, 정교한
  대화형 시스템을 만드는 데 유용합니다. 다만 추가적인 맥락의 뒷받침이 없으면, 그 응답은
  뻔하고 깊이가 없어질 수 있습니다.

LLM을 KG 같은 지식 원천과 통합하면, 대화형 시스템은 자신의 응답을 한층 끌어올릴 수
있습니다. LLM은 KG에 담긴 구조화된 정보를 활용해 더 정확하고 맥락에 맞는 답을 내놓을 수
있습니다. 이 통합 덕분에 시스템은 복잡한 질의를 헤쳐 나가고, 정밀한 정보를 제공하며,
자연스러운 대화 흐름을 유지할 수 있습니다.

#### 1.5.3 KG를 쓸지 말지 판단하기

방금 본 시나리오들은 서로 다르지만 공통된 난제를 안고 있습니다. 다음 질문들은 KG가
여러분의 비즈니스·기술적 난제를 풀 올바른 해법인지 판단하는 데 도움이 됩니다.

다음 질문에 "그렇다"고 답한다면 KG를 고려해 보십시오.

- 서로 흩어진 데이터 사일로를 일관된 개관으로 조화시켜야 하는가?
- 정형·비정형 원천에 걸쳐 데이터를 의미 있게 연결해야 하는가?
- 구조가 진화하는 유연한 데이터 표현이 필요한가?
- 파이프라인의 출처(provenance)와 일관성을 추적해야 하는가?
- 고급 검색·추천 서비스를 갖춰야 하는가?
- 커뮤니티와 상호의존성을 드러내는 네트워크 구조를 시각화해야 하는가?
- 데이터의 관계적 성질에서 이점을 얻는 ML 모델을 적용해야 하는가?

다음 질문에 "그렇다"고 답한다면 LLM을 고려해 보십시오.

- 비정형 데이터에서 개체와 관계를 뽑아내야 하는가?
- 정확한 답을 위해 복잡한 사용자 질의를 해석해야 하는가?
- 대화형 인터페이스를 제공해야 하는가?
- 종합적인 결과를 글로 요약해야 하는가?

이 중 단 하나에라도 "그렇다"고 답한다면, KG 기반 솔루션에 힘을 실어 줄 LLM이 필요합니다.

### 1.6 지식 그래프 기술 — RDF와 LPG, 두 갈래 길

이 책은 특정 기술에 얽매이지 않는 **기술 중립적(technologically agnostic)** 접근을
취하며, KG를 만들고 질의하는 두 가지 대표적 패러다임을 오가는 코드 예제를 제공합니다.

- **RDF와 SPARQL 질의 언어.** 둘 다 W3C(World Wide Web Consortium)가 정의했습니다.
  RDF는 지식 표현에 초점을 둔 데이터 모델로, 그래프를 **진술(statement)** 또는
  **트리플(triplet)** 의 모음으로 인코딩합니다. 웹에서 데이터를 발행하고 공유하는 것을
  표준화하는 것을 목표로 합니다. 이때 지능형 시스템의 핵심은 **의미(semantic) 계층**
  위에서 수행되는 추론에 있습니다.
- **LPG 접근법과 openCypher(<https://opencypher.org/>)·Gremlin
  (<https://tinkerpop.apache.org/gremlin.html>) 같은 질의 언어.** LPG 표현은 그래프의
  **구조(속성과 관계)** 에 초점을 둡니다. 노드와 엣지가 속성을 가지며, 그래프 데이터의
  특징을 강조합니다.

RDF는 표준화된 진술을 통해 시스템 간 **데이터 상호운용성** 과 **일관성** 에서 뛰어나며,
서로 다른 RDF 그래프를 풍부한 맥락 정보와 함께 연결하는 강력한 하이퍼그래프·연합
(federation) 기능을 제공합니다. LPG 구현은 **경로 탐색 질의** 와 **그래프 순회 연산**
에서 이점을 제공합니다. LPG에서는 각 엣지가 고유한 정체성과 속성을 갖지만, RDF에서는
관계가 지식 베이스 전체의 진술들에 걸쳐 재사용될 수 있는 **전역 술어(global
predicate)** 입니다. 이 차이를 실감 나게 풀어 보면, LPG에서 "A가 B에서 태어났다"는
그 관계 하나에 "출처: 위키피디아, 신뢰도: 0.9" 같은 속성을 직접 매달 수 있는 반면,
RDF에서 '태어났다(bornIn)'는 지식 베이스 전체가 공유하는 하나의 술어라서 개별 관계에
꼬리표를 다는 방식이 다릅니다. 그래서 관계 자체에 정보를 풍부하게 붙이려면 LPG가,
서로 다른 데이터셋을 표준적으로 잇고 추론하려면 RDF가 유리합니다.

RDF와 LPG는 서로 구별되는 패러다임이지만, 활용 사례에 따라 상호 보완적일 수 있습니다.
RDF는 의미적 일관성, 웹 규모의 상호운용성, 지식 추론을 위한 온톨로지 활용이 필요한
상황에서 뛰어나고, LPG는 풍부한 속성 기반 표현과 효율적인 그래프 순회를 제공합니다.

#### 1.6.1 분류체계와 온톨로지 — 그래프에 '의미'를 불어넣기

현대적인 KG 구현은 그래프 데이터의 전통적 특징을 활용해야 할 뿐 아니라, [15]가 정의한
대로 **의미가 가능케 하는 조직 원리** 를 활용해야 합니다. 바로 이것이 그래프에 잠재된
지식을 진정한 KG로 바꿔 놓습니다. 그래프 모델은 진술의 모음(RDF)으로부터, 또는 LPG
모델을 통해 만들어질 수 있습니다. 그러나 이런 구조적 정보를 담는 것만으로는 데이터
안의 관계를 온전히 포착하지 못합니다. 우리는 **분류체계(taxonomy)** 와
**온톨로지(ontology)** 를 이용해 이런 의미적 특징을 KG에 주입할 수 있습니다.

- **분류체계(Taxonomy)** 는 데이터의 **계층적 차원** 을 표현하며, 범주들을 넓음–좁음
  관계로 조직합니다. 예를 들어 분류체계에서 "탈것(Vehicle)" 범주는 "자동차(Car)"
  범주보다 넓고, "자동차"는 다시 "세단(Sedan)" 범주보다 넓습니다. 복잡한 KG는 여러
  분류체계를 통합할 수 있습니다.
- **온톨로지(Ontology)** 는 단순한 계층을 넘어서는 더 복잡한 관계를 도입합니다. 개체들
  사이의 동일성, 차이, 그리고 더 정교한 상호연결을 분명히 할 수 있습니다. 예를 들어
  온톨로지는 "자동차(Car)"와 "오토모빌(Automobile)"이 동일하다(동의어)고 명시할 수
  있고, "자동차(Car)"와 "자전거(Bicycle)"는 서로소(disjoint)여서 같은 것일 수 없다고
  명시할 수 있습니다. 온톨로지는 합집합, 여집합, 서로소, 개수 제약(cardinality
  restriction)을 포함한 클래스 정의를 뒷받침합니다. 이렇게 도메인의 개념적 구조를
  포착합니다. 온톨로지가 없으면, 어휘는 개념들 사이의 본질적 관계를 담아내지 못해
  모호한 채로 남습니다. 정리하면, 분류체계가 "무엇이 무엇의 하위인가"라는 세로 방향의
  질서만 잡아 준다면, 온톨로지는 "이 둘은 같다 / 다르다 / 공존할 수 없다" 같은 가로
  방향의 규칙까지 명시해 기계가 스스로 추론할 근거를 마련해 줍니다.

분류체계와 온톨로지를 정의하는 전통적 접근법은 경직되고 복잡해서, 이런 시스템을 진화하는
지식과 다양한 데이터 원천에 잘 적응하지 못하게 만듭니다. 현대적인 KG는 **"딱 필요한
만큼의 의미(just enough semantics)"** 라는 실용적 접근을 취합니다. 이는 지나치게
규범적이지 않으면서 당면한 문제를 해결하는 온톨로지 기능의 일부만 골라 쓰는 것을 뜻합니다.
예를 들어 의료 KG에서 실무자들은 종양학이나 심장학 같은 특정 의학 도메인에 집중하되,
필요할 때 다른 전문 분야로 확장할 여지를 남겨 둘 수 있습니다.

경직되고 완전한 분류체계를 강요하는 대신, 현대적인 KG는 유기적으로 확장할 수 있는
**부분 온톨로지(partial ontology)** 를 통합합니다. 이 유연성 덕분에 현실의 제약과
진화하는 비즈니스 요구에 적응하는, 동적이고 확장 가능한 지식 표현이 가능해집니다.

### 1.7 이 책은 KGs와 LLM을 어떻게 가르치는가

이 책은 KG를 만들고 활용하는 데 꼭 필요한 도구들을 갖춰 주는 한편, 고급 지능형
애플리케이션을 위해 LLM을 활용하는 법을 함께 보여 줍니다. 여러분은 다음을 배우게 됩니다.

- **목표 → 데이터 → 알고리즘** 순으로 초점을 맞추는, 비즈니스 요구 중심의 사고방식
  채택하기
- 미래의 확장, 분류체계, 온톨로지를 고려하며 KG 스키마 모델링하기
- 정형 원천에서 데이터를 가져와 개체·관계를 스키마에 매핑하기
- LLM을 활용해 텍스트에서 도메인 관련 개체와 관계 뽑아내기
- 수집한 정보를 검증해 무결성과 정확성 보장하기
- 그래프 신경망(GNN) 같은 최신 ML 기술로 분석 수행하기
- 그래프의 일부를 질의·시각화하되, 자연어 질문에는 LLM 활용하기

이 개념들은 저자들이 직접 경험에서 길어 올린 구체적이고 실용적인 예시를 통해 설명됩니다.

### 요약

- KG는 유형이 지정된 개체, 속성, 의미 있는 관계를 담은, 끊임없이 진화하는 그래프 데이터
  구조입니다. 특정 도메인을 위해 정형·비정형 데이터로부터 구축되어, 사람과 기계를 위한
  지식을 빚어냅니다.
- KG에는 네 기둥이 있습니다: **진화, 의미, 통합, 학습.**
- KG는 사람의 지식을 기계에 담는 핵심 추상화이고, LLM은 자연어 이해 능력을 제공합니다.
  LLM과 KG는 각자의 한계를 극복하며 서로에게 힘을 실어 줍니다.
- KG와 LLM의 채택은, 지능적 행동이 단일한 신뢰의 원천에 한 번 담기는 패러다임 전환을
  뜻합니다. 이는 서로 다른 애플리케이션과 다양한 과제를 위한 데이터 표현에 힘을 실어
  줍니다.
- KG를 표현하는 두 핵심 기술은 **RDF(Resource Description Framework)** 와 **LPG(labeled
  property graph)** 입니다.
- 분류체계와 온톨로지는 전통적인 그래프를 더 똑똑하게 만드는 의미적 메타데이터를 담아,
  근본적인 역할을 합니다.

## 핵심 용어 해설

| 용어 | 쉬운 설명 |
|------|----------|
| **지식 그래프 (KG, Knowledge Graph)** | 현실의 개체(노드)와 그 사이의 의미 있는 관계(엣지)를 구조적으로 담아, 사람과 기계가 함께 쓰는 검증된 사실 대장 |
| **대규모 언어 모델 (LLM)** | ChatGPT처럼 방대한 텍스트로 학습해 자연어를 이해·생성하는 거대한 AI 모델 |
| **생성형 AI (GenAI)** | LLM이 이끄는, 새로운 텍스트·콘텐츠를 만들어내는 AI |
| **환각 (Hallucination)** | LLM이 그럴듯하지만 사실이 아닌 정보를 지어내는 현상 |
| **노드 / 관계 / 속성** | KG의 세 요소. 노드=개체, 관계=개체 간 연결, 속성=맥락 정보(날짜·좌표 등) |
| **홉 (Hop)** | 그래프에서 한 개념에서 다른 개념으로 건너가는 한 단계 |
| **전이 학습 (Transfer Learning)** | 일반 과제에서 배운 패턴을 특정 과제에 다시 활용하는 학습 방식 |
| **트랜스포머 (Transformer)** | 오늘날 LLM의 기반이 되는 신경망 아키텍처 |
| **PLM (사전학습 언어 모델)** | 대규모 말뭉치로 미리 학습된 언어 모델. LLM은 규모가 큰 PLM |
| **토큰화 (Tokenization)** | 텍스트를 토큰이라는 작은 단위로 잘게 나누는 과정 |
| **데이터 중심 패러다임** | 모델 구조보다 데이터의 품질·양을 끌어올리는 데 집중하는 접근 |
| **상호참조 해소 (Coreference Resolution)** | 대명사 등이 무엇을 가리키는지 알아내는 작업 |
| **GraphRAG** | 지식을 군집·커뮤니티 요약으로 조직해 최신 정보를 LLM에 공급하는 검색 증강 기법 |
| **text-to-cypher** | 자연어 질문을 그래프 질의 언어(Cypher)로 변환하는 것 |
| **단일 진실의 원천 (Single Source of Truth)** | 지능적 행동의 근거를 한 곳에 통일해 담은 신뢰 가능한 원천 |
| **RDF / SPARQL** | W3C 표준. 그래프를 트리플(진술)로 인코딩하는 데이터 모델과 그 질의 언어 |
| **LPG / openCypher / Gremlin** | 노드·엣지의 속성과 구조를 강조하는 그래프 모델과 그 질의 언어 |
| **분류체계 (Taxonomy)** | 범주를 넓음–좁음의 계층 관계로 조직한 것 (예: 탈것 ⊃ 자동차 ⊃ 세단) |
| **온톨로지 (Ontology)** | 계층을 넘어 동일성·차이·서로소 등 개념 간의 복잡한 관계를 정의한 것 |
| **KG의 네 기둥** | 진화(Evolution)·의미(Semantics)·통합(Integration)·학습(Learning) |
